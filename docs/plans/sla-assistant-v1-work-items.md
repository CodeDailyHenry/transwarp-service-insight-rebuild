# SLA 智能诊断 V1 实施工作项

本计划把已确认的 V1 规格拆成可独立验证的纵向工作项。编号表示建议顺序，`Blocked by` 是必须先完成的依赖；每项都应以独立提交交付，并在实现时采用测试先行。

## W01 — 建立后端与 CLI 骨架

**目标**：建立 Python 项目、FastAPI 应用、CLI 包、本地配置、Docker Compose 和基础质量检查。

**验收**：CLI 能访问 `/health/ready`；应用可在本地测试和 Docker Compose 中启动；配置中不包含密钥。

**Blocked by**：无

## W02 — 实现身份、个人令牌与服务端 RBAC

**目标**：实现初始管理员、一次性令牌、令牌哈希、账号禁用、令牌重置以及 `user`/`curator`/`admin` 授权。

**验收**：三个角色的权限矩阵具备接口测试；隐藏管理帮助不能绕过服务端授权；审计日志不记录明文令牌。

**Blocked by**：W01

## W03 — 定义并校验产品 Skill 包

**目标**：实现 Skill Registry，加载 `metadata.yaml`、提示词、流程和知识目录；提供最小 ArgoDB Skill。

**验收**：合法 Skill 可加载，缺少字段或别名冲突会产生可操作错误；Skill 可通过后端列出，普通用户不可发布修改。

**Blocked by**：W01、W02

## W04 — 实现来源导入与对象存储

**目标**：导入首版文件类型，保存原始来源、内容哈希、解析结果和来源定位，并执行基础敏感信息识别。

**验收**：重复文件可识别；解析失败可追踪且不产生半发布知识；原始内容与元数据分离保存。

**Blocked by**：W01、W02

## W05 — 实现候选知识提炼与发布生命周期

**目标**：从来源或会话生成候选知识，支持编辑、送审、拒绝、发布、撤回和回滚，并产生不可变版本。

**验收**：只有 `admin` 能发布、撤回和回滚；状态机拒绝非法转换；所有变更可审计。

**Blocked by**：W03、W04

## W06 — 实现可追溯混合检索

**目标**：在适配器接缝后实现元数据过滤、关键词/稀疏检索、向量检索和重排，只索引已发布知识。

**验收**：每个命中能还原知识版本和来源定位；撤回后重建或增量更新索引均不会返回旧知识；使用内存适配器的契约测试覆盖同一接口。

**Blocked by**：W05

## W07 — 实现会话、诊断状态与上下文压缩

**目标**：创建诊断会话，保存消息、自然语言摘要和结构化诊断状态，实现 clear、手动 compact 和阈值自动 compact。

**验收**：压缩前后关键版本、错误码和已尝试操作不丢失；clear 后不存在旧问题事实；退出后新会话默认不恢复旧状态。

**Blocked by**：W01、W02

## W08 — 实现 Skill 路由与追问

**目标**：支持手动锁定、自动路由、低置信度候选追问，以及主 Skill 加关联 Skill。

**验收**：路由结果包含置信度和真实依据；低置信度不静默选择；首批人工路由样例可重复运行。

**Blocked by**：W03、W07

## W09 — 实现证据约束回答与研发升级摘要

**目标**：编排诊断、检索、来源优先级、冲突处理、证据校验、风险分级、流式回答和升级摘要。

**验收**：无证据、版本缺失、来源冲突和高风险样例分别走正确分支；回答中的引用和检索轨迹可核验；高风险操作不输出破坏性指令。

**Blocked by**：W06、W07、W08

## W10 — 完成 `sla ask` 交互式 CLI

**目标**：实现完整 REPL、角色化帮助、会话命令、流式显示、来源查看、详细模式和可复制升级摘要。

**验收**：规格第 5 节的命令均有端到端测试；网络或模型错误不会破坏终端状态；CLI 不直接访问数据库、索引或对象存储。

**Blocked by**：W02、W07、W09

## W11 — 实现反馈与会话知识提议

**目标**：保存 helpful/unhelpful 反馈，并把当前会话脱敏提炼为候选知识。

**验收**：普通用户可提议但不能发布；候选知识保留会话来源和脱敏记录；反馈能关联到具体回答及知识版本。

**Blocked by**：W05、W09、W10

## W12 — 建立 ArgoDB 评测集与评测运行器

**目标**：建立 50 至 100 个标注问题的数据格式、评测运行器和人工评分流程，计算路由、引用、可用答案与拒答/追问指标。

**验收**：同一配置可重复运行并输出机器可读结果和摘要；失败案例能追溯到模型、Skill、知识和检索轨迹版本。

**Blocked by**：W09

## W13 — 完成 ArgoDB 纵向验收与运维交付

**目标**：导入真实 ArgoDB 资料，发布首批知识，运行安全测试和固定评测，完成备份、恢复与索引重建说明。

**验收**：达到规格第 13 节全部门槛；Docker Compose 从空环境可部署；完成一次数据恢复和索引重建演练。

**Blocked by**：W10、W11、W12

## 并行路径

依赖允许时可以并行推进：

- W03 与 W04 在 W02 后并行。
- W06 与 W07 在各自前置完成后并行。
- W10、W11 和 W12 按阻塞边逐步汇合到 W13。

首个实现切片应为 W01，不应同时铺开 Inceptor、HDFS 或 TCOS。
